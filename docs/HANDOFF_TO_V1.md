## 1. Décisions transverses (à respecter)
- **Sales Tax = Shopify, seule source de vérité.** On envoie l'adresse complète à `draftOrderCalculate`
  et on utilise les `taxLines` telles quelles. **NE PAS** réintroduire la table `zipToState` ni le
  « bypass Markets » de la V1 (déprécié).
- **Sécurité — NE PAS reproduire** : backdoor `admin_secours`, mots de passe en clair,
  `GET /api/users` exposant les mots de passe, stockage JSON éphémère. (V2 = bcrypt+JWT+Postgres.)
- **Moteur SKU/ID** : la V2 reproduit la V1 à 100 % (SKU 285/285) ; règles d'ID portées fidèlement
  (voir §2.1). Si la V1 reste le socle, c'est déjà conforme — rien à changer côté moteur.

## 2. Inventaire des ajouts V2 (par module)

### 2.1 Admin / référentiel
- **Générateur d'ID fidèle V1** : `api/src/services/sku.ts` → `generateRefId(category, name, existing)`
  (règles `configPrefixMap` + `skuCategoriesConfig` + `autoGeneratedCategories` : modèles `AA###`,
  couleurs `###` ignore ≥900, matières `CU/CE###`, fournisseurs/ateliers/bijouterie `FOU-/ATE-/BIZ-###`,
  années 2 chiffres, saisons H/E). **La V1 a déjà cette logique** (app.js l.1757-1872) — référence si besoin.
- **Import « base complète »** : un seul CSV `category;code;label` → `services/import.ts` `importRefFullCsv`.
- **Export CSV** de toute la base → `exportRefCsv` + route `GET /api/ref/export`.
- **Tri par code (ID)** des référentiels et de la collection.
- Front : `web/src/pages/Admin.tsx` (modes d'import, bouton Export, bouton « Générer »).
- *Portage V1* : logique pure (CSV + génération) → transposable en JS sans dépendance.

### 2.2 PLM Collection
- **Galerie de vignettes** + **fiche animée** + **PRI / marge en direct** : `web/src/pages/Collection.tsx`.
- **Médias multi-images** : modèle `ProductImage` (migration `plm_media_comments_workflow`) ;
  routes `PUT /api/products/:id/images`.
- **Commentaires** : modèle `ProductComment` ; `GET/POST /api/products/:id/comments`.
- **Workflow** : `ProductStatus` + `IN_REVIEW` ; `Product.validatedAt/validatedBy` ; route PUT trace la validation.
- *Portage V1* : nécessite des tables (images/commentaires) → en V1 (JSON), prévoir des collections
  équivalentes ; le workflow = un champ statut + horodatage.

### 2.3 POS / Caisse
- **Switch USD/EUR adapte le formulaire** (préfixe tél +1/+33, pays US/FR) : `web/src/pages/Pos.tsx`
  (effet sur `currency`). La V1 a déjà `switchCurrency()` (app.js l.1116) — comportement identique.
- **Sélection catalogue par vignettes** (modèles → déclinaisons, fil d'Ariane + retour + filtre) :
  `web/src/components/Configurator.tsx` (remplace les listes déroulantes).
- **Validation d'adresse non bloquante** (l'absence de quote Shopify n'empêche pas la vente).
- **Retrait des alertes de dispo** dans le panier (les fiches incomplètes restent un sujet PLM).
- **Frais de port en lecture seule** (définis dans Admin, pas au panier).
- **Messages d'envoi du lien soignés et bilingues** FR/EN (prénom client, objet+corps email).
- *Portage V1* : front pur ; le configurateur vignettes est un patron React à transposer.

### 2.4 Lien de paiement `/pay/:id`
- **Anti-blocage navigateurs in-app** (WhatsApp/Instagram/Messenger…) : détection UA →
  **suppression de l'auto-redirect** + aide « ouvrir dans Safari/Chrome » ; **bilingue** EN/FR.
  Fichier : `api/src/routes/pay.ts`. **La V1 a déjà cette logique** (server.js l.331-398) — equivalent.

### 2.5 Acompte / solde + Devis / Facture (la grosse feature)
Spec complète : `docs/FEATURE_ACOMPTE_DEVIS_FACTURE.md`. Résumé :
- **Modèle** (migration `sale_payment_plan`) : `Sale.paymentPlan` (FULL|DEPOSIT_50), `depositCents`,
  `balanceCents`, `depositPaidAt`, `balancePaidAt`, `depositSessionId`, `balanceSessionId`,
  `documentType` ; statut `AWAITING_BALANCE`.
- **Stripe** : `createPaymentLink(saleId, leg)` (full|deposit|balance) ; webhook routé par `metadata.leg`.
  Fichier `api/src/services/payments.ts`.
- **Logique** : `markDepositPaid` (→ Order Shopify **partiellement payée** + production lancée),
  `markBalancePaid` (→ Order **payée** via `orderMarkAsPaid`). Fichier `api/src/services/sales.ts`.
- **Shopify** : `createRecoveryOrder` accepte `financialStatus: PARTIALLY_PAID` + transaction d'acompte ;
  `markShopifyOrderPaid`. Fichier `api/src/services/shopify.ts`.
- **PDF devis/facture** : `api/src/services/invoice.ts` (lib **pdfkit**, gabarit « Balance Invoice »
  bilingue fidèle à la maquette `Tiraboschi_Invoice_1023.pdf`) ; route `GET /api/pos/sales/:id/document?type=quote|invoice`.
- **Alertes** : `GET /api/pos/sales/alerts` (acomptes/soldes en attente).
- **Relance** : 2ᵉ lien généré depuis Sales **sans re-saisie** (`leg=balance`).
- **Front** : `web/src/pages/Pos.tsx` (sélecteur 100%/50-50, boutons Devis/Facture),
  `web/src/pages/Sales.tsx` (statut « Solde dû », bandeau d'alertes, relance/solde, PDF).
- *Portage V1* : dépend d'une persistance fiable (statuts acompte/solde durables). En V1 (JSON),
  c'est le point sensible — voir la mise en garde de `MIGRATION_V1_V2.md`.
- **Reste à brancher** : envoi email **avec PDF en pièce jointe** (nécessite un provider SMTP/SendGrid
  ou l'email de facture Shopify). Aujourd'hui : téléchargement du PDF + partage du lien.
